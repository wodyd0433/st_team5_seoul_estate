# Streamlit 대시보드 보강 계획

본 문서는 `gpt_analysis` Streamlit 대시보드를 보강하기 위한 실행 계획서이며, 현재 단계에서는 코드 수정 없이 방향과 검증 기준만 정리한다. 목표는 `data_all`에 새로 포함된 데이터(`seoul_mart.csv`, `DT_1NW1027.csv`)를 반영하고, 추천 결과에 사용되는 수치가 어떤 데이터로부터 어떻게 계산되었는지 사용자가 추적 가능하도록 만드는 것이다.

## 1. 반영 대상과 목표

### 1-1. `seoul_mart.csv` 반영
- 의미: 대형마트 및 유통 시설 데이터
- 활용 목표: 기존 병원/공원/유통 인프라 점수 체계를 보강하여 생활 편의성 점수에 반영
- 구현 방향:
  - `seoul_mart.csv`에서 서울시 자치구별 유효 영업점 수를 집계한다.
  - 폐업/비정상 영업 상태는 제외하고 현재 운영 중인 시설만 집계한다.
  - 기존 `retail_license_count`는 원천 데이터인 `distribution_license.csv`가 제거되었으므로 대시보드와 계산식에서 삭제한다.
  - 병원, 공원, 대형마트를 기준으로 별도 `mart_count` 지표를 생성한다.
  - 인프라 점수는 단순 합계가 아니라 표준화 후 가중합으로 재설계한다.
  - 대시보드에는 “병원 수”, “공원 수”, “대형마트 수”, “생활 인프라 종합점수”를 분리해서 보여준다.

### 1-2. `DT_1NW1027.csv` + `debt_newlyweds.csv` 반영
- 의미:
  - `DT_1NW1027.csv`: 신혼부부 소득 구간 분포 자료
  - `debt_newlyweds.csv`: 신혼부부 대출 보유 비율, 금융권 대출잔액 구간, 대출잔액 중앙값 자료
- 활용 목표: 단순 현재 추천이 아니라 “향후 2~3년 내 구매 가능성”을 포함한 소득+부채 기반 페르소나 대시보드 추가
- 구현 방향:
  - `DT_1NW1027.csv`에서 소득 구간 분포를 읽고, `debt_newlyweds.csv`에서 부채 구간 및 중앙값을 함께 읽는다.
  - 페르소나는 소득만이 아니라 `소득 수준`, `대출 보유 여부`, `대출잔액 구간`, `추정 순자산 형성 속도`를 함께 기준으로 만든다.
  - 최소 4~5개 페르소나로 확장한다.
  - 예시:
    - `고소득 저부채 맞벌이`: 소득 상위, 대출잔액 낮음, 매수 전환 가능성 높음
    - `고소득 고부채 맞벌이`: 소득은 높지만 기존 부채 부담이 커서 DSR 관점에서 보수적 접근 필요
    - `중간소득 저부채 성장형`: 현재는 전세 적합, 2~3년 저축 후 일부 자치구 매수 가능
    - `중간소득 고부채 방어형`: 전세 유지 또는 월세 부담 관리가 우선
    - `저소득 저부채 안정형`: 주거비 안정성과 통근, 인프라 중심 추천
  - 각 페르소나별로 현재 전세 가능 지역, 현재 월세 부담 가능 지역, 2년 후 추정 종잣돈, 3년 후 추정 종잣돈, 기존 대출 반영 후 실질 매수 가능 범위를 계산한다.
  - 구매 가능성 시뮬레이션에는 `현재 소득 구간`, `현재 추정 부채잔액`, `저축률 가정`, `금리/대출한도 가정`, `자기자본 비율`을 함께 명시한다.
  - 단, 두 파일 모두 집단 통계이므로 개별 가구의 실제 금융 상태를 직접 의미하지 않는다. 따라서 대시보드에는 “통계 기반 페르소나 시뮬레이션”이며, 실제 대출 가능액과 매수 가능성은 개인 심사 결과와 다를 수 있음을 명확히 표시한다.

## 2. 점수 계산 로직 문서화 계획

점수 계산 방식은 별도 MD 문서로 저장하며, 사용자가 숫자의 출처를 추적할 수 있도록 항목별 계산식을 명시한다. 최소 포함 내용은 아래와 같다.

- `예산 점수`
  - 자치구별 대표 전세금 또는 월세/보증금 조합을 기준으로 예산 상한 대비 적합도를 계산
  - 예: `예산 점수 = 1 - min(대표주거비 / 사용자 예산상한, 1)`
- `통근 점수`
  - 권역 CSV의 소요시간(분)을 기반으로 자치구별 대표 통근시간을 산출
  - 2인 가구는 `직장1 통근시간`, `직장2 통근시간`, `최장 통근시간`, `평균 통근시간`을 모두 보관
- `치안 점수`
  - 범죄 건수와 경찰 만족도를 각각 정규화
  - 범죄는 낮을수록 높은 점수, 만족도는 높을수록 높은 점수
  - 두 값을 별도 축으로 보여주고, 종합 치안 점수는 가중합으로 계산
- `인프라 점수`
  - 병원 수, 공원 수, 유통 관련 점포 수, 대형마트 수를 각각 정규화
  - 레이더 차트 대신 지표별 막대/도트/랭킹 비교 방식으로 재구성
- `종합 점수`
  - `종합 점수 = 예산 가중치 * 예산 점수 + 통근 가중치 * 통근 점수 + 치안 가중치 * 치안 점수 + 인프라 가중치 * 인프라 점수`
  - 추가로 균형형 패널티나 편향 보정이 있으면 별도 항목으로 문서화

## 3. 데이터 출처와 파생 데이터 명시 계획

별도 MD 문서에는 각 데이터셋의 출처와 대시보드 사용 위치를 표로 정리한다.

- `apt_deal_total.csv`: 국토교통부 아파트 매매 실거래 파생 데이터
- `seoul_apt_rent_5y.csv`: 서울 아파트 전월세 파생 데이터
- `crime_2024.csv`: 자치구별 범죄 집계 데이터
- `police_satisfaction_2025.csv`: 경찰서 단위 만족도 조사 데이터
- `hospital_data.csv`, `hospital.db`: 병원 인프라 데이터
- `seoul_parks.csv`, `seoul_parks_stats.csv`: 공원 데이터 및 자치구 집계 데이터
- `seoul_mart.csv`: 대형마트 데이터
- `DT_1NW1027.csv`: 신혼부부 소득 분포 데이터
- `debt_newlyweds.csv`: 신혼부부 부채 보유 비율 및 금융권 대출잔액 분포 데이터
- `25.12기준.서울시정비사업추진현황.csv`: 정비사업 현황 데이터
- `*_time_zones*.csv`: 주요 업무지 통근권 데이터

또한 조인, 그룹화, 피벗이 일어난 경우 반드시 “어느 원천 데이터에서 어떤 기준으로 만든 파생값인지”를 함께 적는다.

- 예시 1: `crime_score_proxy`는 `crime_2024.csv`에서 자치구 열을 melt 후 자치구별 총 범죄 건수로 집계한 값
- 예시 2: `police_satisfaction_score`는 `police_satisfaction_2025.csv`에서 경찰서명을 자치구로 매핑 후 자치구 평균으로 집계한 값
- 예시 3: `mart_count`는 `seoul_mart.csv`에서 정상 영업만 남기고 자치구별 그룹화한 값
- 예시 4: 기존 `retail_license_count`는 `distribution_license.csv` 원천 제거에 따라 폐기하고, 이후 문서와 화면에서 사용하지 않는다.
- 예시 5: `yearly_rent`는 `자치구별_아파트_전월세_평균20XX.csv`를 연도별로 읽어 결합한 값
- 예시 6: `persona_income_band`는 `DT_1NW1027.csv`의 소득 구간 분포에서 정의한 페르소나 기준값
- 예시 7: `persona_debt_band`와 `persona_debt_median`은 `debt_newlyweds.csv`의 대출잔액 구간 및 중앙값에서 정의한 페르소나 기준값

## 4. 캡처 기준 화면 개선 계획

### 4-1. 변수명 한글화
- 범례, 축, 툴팁, 컬럼명에서 영문 내부 변수명을 직접 노출하지 않는다.
- 예:
  - `crime_score_proxy` → `범죄 발생 지표`
  - `police_satisfaction_score` → `경찰 만족도`
  - `redevelopment_count` → `정비사업 구역 수`
  - `active_stage_count` → `활성 추진 단계 수`

### 4-2. 치안 그래프 개선
- 현재 막대 2개를 한 축에 놓으면 해석이 어렵다.
- 범죄 지표와 경찰 만족도는 단위가 다르므로 이중축 그래프로 변경한다.
- 왼쪽 축은 범죄 건수 또는 범죄 역점수, 오른쪽 축은 경찰 만족도로 분리한다.

### 4-3. 인프라 시각화 개선
- 현재 레이더 차트는 축 단위가 다르고 선이 겹쳐 해석성이 낮다.
- 대체안:
  - 상위 10개 자치구만 비교하는 그룹 막대차트
  - 자치구 선택 시 지표 카드 + 수평 막대 차트
  - 산점도는 유지하되 마트 수를 점 크기 또는 색상으로 추가
- “인프라 종합점수”는 반드시 하위 지표와 함께 설명한다.

### 4-4. 금액 형식 통일
- 전세, 월세, 매매가, 예산, 추정 종잣돈 등 모든 금액은 회계 형식으로 표기한다.
- 예: `700000000` → `700,000,000원`
- 차트 축도 가능하면 `억원`, `만원` 중 하나로 통일하고 툴팁에는 원 단위 콤마 표기 적용

### 4-5. 2인 가구 통근시간 표현
- 추천 요약 카드와 표에서 2인 가구는 통근시간을 합치지 않고 각각 표시한다.
- 예:
  - `직장1 통근시간`
  - `직장2 통근시간`
  - `최장 통근시간`
  - 필요 시 `평균 통근시간`

## 5. 가상 데이터 사용 여부 검증 계획

가상 데이터가 없는지 확인하는 작업은 기능 구현과 별도로 체크리스트화한다. 특히 추천 요약의 전세, 월세, 통근, 평수는 아래처럼 검증한다.

- `전세`
  - 원천: `seoul_apt_rent_5y.csv` 또는 연도별 평균 전월세 CSV
  - 계산: 자치구 + 면적구간 + 선택연도 기준 대표값(평균/중앙값)을 사용했는지 명시
- `월세`
  - 원천: `seoul_apt_rent_5y.csv`
  - 계산: 보증부 월세와 순수 전세를 구분하고, 실제 표시값이 어떤 필터 결과인지 문서화
- `통근`
  - 원천: `Gwanghwamun_time_zones.csv`, `gangnam_time_zones_20260227.csv`, `seongsu_time_zones_20260227.csv`, `yeouido_time_zones_20260224.csv`
  - 계산: 역 단위 데이터를 자치구 단위 대표값으로 바꾸는 규칙을 명시
- `평수`
  - 원천: 사용자가 선택한 평수 구간
  - 계산: `평 = m2 / 3.3058` 변환을 사용했는지, 추천 결과의 실제 표시는 m2와 평을 함께 보여주는지 확인

별도 MD 문서에는 “가상으로 생성한 값”과 “원천 데이터에서 직접 가져온 값”을 구분해서 적는다. 예를 들어 페르소나별 2~3년 후 구매 가능성은 원천 데이터가 아니라 소득, 기존 부채, 저축률, 금리, 대출 가정이 들어간 시뮬레이션 값이므로, 반드시 가정값과 계산식을 함께 노출해야 한다.

## 6. 구현 순서 제안

1. 루트 `data_all` 기준으로 원천/파생 데이터 목록을 다시 확정
2. `seoul_mart.csv` 집계 규칙 정의 및 인프라 점수 재설계
3. `DT_1NW1027.csv`와 `debt_newlyweds.csv` 기반 페르소나 설계와 구매 가능성 산식 확정
4. 추천 요약 카드/표의 실제 계산 근거 추적 컬럼 정리
5. 치안/인프라 시각화 개편
6. 상세 로직 문서 MD 작성
7. “가상 데이터 없음 / 시뮬레이션 값 구분” 검증 문서 MD 작성

## 8. 페르소나 정의표 초안

아래 표는 구현 전 기준의 초안이며, 실제 수치는 `DT_1NW1027.csv`와 `debt_newlyweds.csv`에서 읽은 구간 분포와 중앙값을 바탕으로 보정한다.

| 페르소나 | 소득 기준 | 부채 기준 | 해석 | 우선 추천 방향 |
| --- | --- | --- | --- | --- |
| 고소득 저부채 맞벌이 | 소득 상위 구간 | 대출잔액 낮음 | 매수 전환 여력이 높고 전세 대안도 넓음 | 2~3년 내 매수 가능 지역 중심 |
| 고소득 고부채 맞벌이 | 소득 상위 구간 | 대출잔액 높음 | 소득은 높지만 기존 금융부담이 커서 실질 구매력 재계산 필요 | 전세/매수 병행 비교 |
| 중간소득 저부채 성장형 | 중간 소득 구간 | 대출잔액 낮음 | 저축을 통해 종잣돈을 빠르게 늘릴 수 있는 유형 | 2년 후 매수 진입 가능 지역 |
| 중간소득 고부채 방어형 | 중간 소득 구간 | 대출잔액 높음 | 부채 관리가 우선이며 무리한 매수는 비추천 | 전세 안정성, 통근, 생활 인프라 중심 |
| 저소득 저부채 안정형 | 소득 하위 구간 | 대출잔액 낮음 | 주거비 안정과 이동 편의가 핵심 | 전세/월세 방어형 추천 |
| 저소득 고부채 취약형 | 소득 하위 구간 | 대출잔액 높음 | 금융 부담이 커서 매수 시뮬레이션은 보수적으로 제한 | 주거비 최적화, 위험 경고 강화 |

### 페르소나 필드 정의 초안

- `persona_name`: 화면에 노출할 페르소나 이름
- `income_band_label`: 소득 구간 라벨
- `income_band_source_value`: 소득 구간의 원천 통계값 또는 대표값
- `debt_band_label`: 대출잔액 구간 라벨
- `debt_median_krw`: 해당 집단의 대표 대출잔액
- `debt_holding_ratio`: 부채 보유 비율
- `monthly_income_estimate_krw`: 월소득 추정치
- `monthly_debt_service_estimate_krw`: 월 상환 부담 추정치
- `monthly_saving_estimate_krw`: 월 저축 가능액
- `seed_money_2y_krw`: 2년 후 종잣돈 추정치
- `seed_money_3y_krw`: 3년 후 종잣돈 추정치
- `buying_power_2y_krw`: 2년 후 실질 매수 가능 예산
- `buying_power_3y_krw`: 3년 후 실질 매수 가능 예산

## 9. 계산식 초안

### 9-1. 소득 추정

- 원칙: `DT_1NW1027.csv`의 소득 구간을 월 기준 추정 소득으로 변환
- 방식:
  - 구간형 자료는 구간 중앙값을 대표값으로 사용
  - 최상위 개방 구간은 별도 상한 가정값을 문서에 명시
- 예시:
  - `연소득 추정값 = 소득구간 대표값`
  - `월소득 추정값 = 연소득 추정값 / 12`

### 9-2. 부채 추정

- 원칙: `debt_newlyweds.csv`의 대출잔액 구간 및 중앙값을 사용
- 방식:
  - 우선 집단별 `대출잔액 중앙값(만원)`을 대표 부채로 사용
  - 중앙값이 없거나 해석이 애매한 경우 구간 중앙값 사용
- 예시:
  - `기존 부채 추정값 = 대출잔액 중앙값 * 10,000`

### 9-3. 월 상환 부담 추정

- 원칙: 기존 부채가 있으면 단순 잔액이 아니라 월 상환 부담으로 환산
- 예시:
  - `월 상환 부담 = 기존 부채 추정값 * 부채상환계수`
- 부채상환계수는 금리, 만기 가정에 따라 별도 설정표로 관리

### 9-4. 월 저축 가능액 추정

- 예시:
  - `월 저축 가능액 = 월소득 추정값 - 월 생활비 가정 - 월 주거비 가정 - 월 상환 부담`
- 생활비 가정은 페르소나별 고정 비율 또는 고정 금액 중 하나로 통일

### 9-5. 종잣돈 추정

- 예시:
  - `2년 후 종잣돈 = 현재 보유자금 가정 + 월 저축 가능액 * 24`
  - `3년 후 종잣돈 = 현재 보유자금 가정 + 월 저축 가능액 * 36`

### 9-6. 실질 매수 가능 예산

- 예시:
  - `실질 매수 가능 예산 = 종잣돈 + 추가 차입 가능액 - 기존 부채 조정액`
- 추가 차입 가능액은 다음 두 방식 중 하나를 선택
  - 소득 배수 기반
  - 월 상환 가능액 기반
- 어느 방식을 쓰는지 문서에 고정하고, 혼용하지 않는다.

### 9-7. 자치구별 매수 가능성 판정

- 자치구 대표 매매가와 비교하여 3단계로 분류
- 예시:
  - `실질 매수 가능 예산 >= 자치구 대표 매매가`: 매수 가능
  - `실질 매수 가능 예산 >= 자치구 대표 매매가 * 0.85`: 도전 가능
  - 그 외: 현재 시점 매수 어려움

### 9-8. 자치구별 전세/월세 가능성 판정

- 전세:
  - `전세 적합 = 자치구 대표 전세금 <= 페르소나 전세 예산 상한`
- 월세:
  - `월세 적합 = 대표 보증금 <= 보증금 상한` 그리고 `대표 월세 <= 월세 상한`

## 10. 구현 전 검증 체크리스트

- `DT_1NW1027.csv`의 소득 구간 정의가 연소득 기준인지 월소득 기준인지 명확히 확인
- `debt_newlyweds.csv`의 헤더 구조가 다중 행 형태이므로 정규화 규칙을 먼저 확정
- 소득 구간 대표값과 부채 구간 대표값을 어떤 방식으로 정하는지 문서에 고정
- 페르소나별 가정값과 원천 통계값을 화면에서 구분 표기
- 추천 결과의 `전세`, `월세`, `통근`, `평수`, `매수 가능성`이 각각 어떤 원천과 산식에서 왔는지 추적 가능해야 함
- 시뮬레이션 수치에는 반드시 “추정” 또는 “가정 기반” 표기를 붙임

## 11. `debt_newlyweds.csv` 전처리 규칙 초안

`debt_newlyweds.csv`는 일반적인 단일 헤더 CSV가 아니라, 상단 2개 행이 사실상 컬럼 설명 역할을 하는 다중 헤더형 표에 가깝다. 따라서 구현 전에 “어떻게 평탄화(flatten)할 것인지”를 문서로 고정해야 한다.

### 11-1. 원본 구조 해석

현재 확인된 구조는 다음과 같다.

- 첫 번째 열: `신혼부부 특성별(1)`
- 두 번째 열: `신혼부부 특성별(2)`
- 이후 연도 컬럼들: `2024`, `2024.1`, `2024.2` ... `2024.10`
- 실질적으로 1행과 2행이 각각 “상위 분류명”, “세부 분류명” 역할을 하고 있음

즉 파일을 그대로 읽으면 컬럼명이 불안정하고, 실제 데이터 행과 설명 행이 섞여 있기 때문에 바로 집계에 쓰면 안 된다.

### 11-2. 전처리 기본 규칙

1. 첫 2개 행을 메타 헤더로 분리한다.
2. 3번째 행부터 실제 데이터 행으로 간주한다.
3. 두 개의 특성 열은 다음처럼 이름을 고정한다.
   - `feature_major`
   - `feature_minor`
4. 연도 계열 열은 상위 헤더와 하위 헤더를 합쳐 고정 컬럼명으로 평탄화한다.

### 11-3. 평탄화 컬럼명 규칙

예시 변환 규칙은 다음과 같다.

- `2024` + `보유 부부 비율 (%)` → `debt_holding_ratio_pct`
- `2024.1` + `합계` → `debt_band_total_pct`
- `2024.2` + `1천만원 미만` → `debt_lt_10m_pct`
- `2024.3` + `1천만원~3천만원 미만` → `debt_10m_30m_pct`
- `2024.4` + `3천만원~5천만원 미만` → `debt_30m_50m_pct`
- `2024.5` + `5천만원~7천만원 미만` → `debt_50m_70m_pct`
- `2024.6` + `7천만원~1억원 미만` → `debt_70m_100m_pct`
- `2024.7` + `1억원~2억원 미만` → `debt_100m_200m_pct`
- `2024.8` + `2억원~3억원 미만` → `debt_200m_300m_pct`
- `2024.9` + `3억원 이상` → `debt_ge_300m_pct`
- `2024.10` + `대출잔액 중앙값 (만원)` → `debt_median_manwon`

이 규칙은 영문 snake_case 내부 컬럼으로 관리하되, 화면 표기와 문서 표기는 한국어로 변환해서 노출한다.

### 11-4. 행 구조 정리 규칙

행도 단순하지 않으므로 다음 규칙을 적용한다.

1. `feature_major`, `feature_minor`가 모두 헤더 반복 문자열인 행은 제거
2. `소계`, `합계` 같은 전체 집계 행은 유지하되, 세부 집단 행과 구분 플래그를 둔다
3. 페르소나 설계에 직접 쓰는 집단만 우선 사용한다
   - 예: 전체 신혼부부, 맞벌이 여부, 자녀 여부, 혼인기간 등
4. 분석 단계에서 사용하지 않을 세부 분류는 원본 보존 후 2차 단계에서 제외 가능하도록 둔다

### 11-5. 파생 필드 생성 규칙

전처리 후 아래 파생 필드를 추가 생성하는 설계가 적절하다.

- `debt_band_mode`
  - 가장 비중이 높은 대출잔액 구간
- `debt_band_weighted_midpoint_manwon`
  - 구간 비중을 활용한 가중 평균 대출잔액 추정치
- `debt_risk_level`
  - 저부채 / 중부채 / 고부채 분류
- `debt_profile_label`
  - 화면용 설명 라벨

### 11-6. 페르소나 연결 규칙

`debt_newlyweds.csv`는 개별 가구 데이터가 아니므로 특정 한 자치구와 직접 연결하지 않는다. 대신 아래 순서로 쓴다.

1. `DT_1NW1027.csv`에서 소득축 정의
2. `debt_newlyweds.csv`에서 부채축 정의
3. 두 축을 조합해 페르소나 정의 테이블 생성
4. 각 페르소나에 대해 주거비/통근/매수 가능성 시뮬레이션 적용

즉 `debt_newlyweds.csv`는 “추천 지역 원천 데이터”가 아니라 “페르소나 재무 상태 설정 데이터”로 쓴다.

### 11-7. 문서화 원칙

이 파일을 활용해 만든 값은 다음 세 층으로 구분해서 문서화한다.

- 원천값:
  - 부채 보유 비율
  - 대출잔액 구간 비중
  - 대출잔액 중앙값
- 전처리 파생값:
  - 대표 부채 구간
  - 가중 평균 부채 추정값
  - 부채 위험 레벨
- 시뮬레이션 값:
  - 월 상환 부담 추정
  - 순저축 가능액
  - 2년/3년 후 종잣돈
  - 실질 매수 가능 예산

### 11-8. 구현 전 확정 필요 항목

- `대출잔액 중앙값 (만원)`을 최우선 대표값으로 쓸지 --> OK
- 구간 비중 기반 가중 평균을 보조지표로만 둘지 --> 알아서
- 어떤 집단 구분을 페르소나 축으로 채택할지 --> 맞벌이
- 부채 수준을 몇 단계로 자를지 --> 3단계가 적당
- 부채가 있는 가구와 없는 가구를 완전히 분리해 페르소나를 만들지 --> 현재 페르소나 유지
